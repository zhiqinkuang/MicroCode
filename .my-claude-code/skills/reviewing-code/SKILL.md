# 代码审查

先阅读真实 diff 和附近的调用链，再给出结论。

1. 找出行为变化，以及能触发这些变化的输入。
2. 检查错误路径、边界条件，以及现有调用方的兼容性。
3. 确认测试既覆盖预期行为，也覆盖最可能发生的回归。
4. 只报告可执行的问题，并说明受影响的文件、具体失败方式和最小安全修复建议。

仅当改动涉及数据库 schema 或数据迁移时，继续读取 `references/database.md`。
